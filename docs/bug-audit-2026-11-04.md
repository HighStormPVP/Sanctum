# Sanctum bug audit, 4 November 2026

**Status: 50 have a fix in the working tree, not yet committed. 51 (no app icon) was undone at the owner's request, because they prefer Electron's default icon.** Line numbers are from before the fixes, so they won't match the code now.

Checked with `npm test` (41 tests) and 76 checks driving the real app against a fake Ollama and stubbed cloud APIs.

**Fixed but not exercised for real:**

- Live Claude and Gemini calls, including image sending, thinking settings, fallbacks, and signatures. These ran against stubbed responses only.
- Whisper itself (13). Only the line-ending handling was tested.
- Stop during video stages (23), and the video summary on cloud models (35).
- Killing a real MCP server's process tree (24), and spawning one through the new quoting (38).
- macOS and Linux behaviour (39, 40). This was tested on Windows only.
- The packaged app, including running from the app archive.

**Remaining risk, by design:**

- `web_fetch` (8) can no longer reach local addresses, but it still runs without a prompt in Plan Mode. A malicious page could still get the model to put file contents in a public URL. Turning on No-Fetch or using Approval Mode closes this.
- There's a small gap between the DNS check and the connection in `web_fetch`, so a hostile DNS server could in theory still reach a local address.
- Pre-approved commands (3) can't chain or redirect anymore, but arguments aren't limited. Allowing `git` also allows `git push`.

How each finding was checked:

- **Confirmed**: the code was re-read directly after the audit.
- **Reproduced**: an isolated script showed the behaviour, outside Electron.
- Everything else comes from a reviewer reading the code, without running it.

## Agent safety

These matter most, because the model can reach your files and shell.

1. **Safety settings follow the chat on screen, not the chat that's running** (Confirmed). `renderer.js:5346`, `renderer.js:5365`. Chat A in Plan Mode can write files without asking if you switch to a No-Approval chat. Fix: pass the running chat into `executeTool`.
2. **MCP tools skip Plan Mode and Read-Only, and only prompt in Approval Mode** (Confirmed). `renderer.js:5391`, `renderer.js:5428`, `renderer.js:5440`. Fix: treat `mcp__*` as gated.
3. **Pre-approved commands match on a prefix** (Confirmed). `renderer.js:5379`. With `git status` allowed, `git status && rm -rf ~` runs without asking. Fix: match whole commands and reject shell operators.
4. **`../` can escape the project folder** (Reproduced). `main.js:2255`, `main.js:2264`. `C:\proj\..\Windows\win.ini` passes the check, and reads don't prompt. Fix: resolve the path before checking, and compare case-insensitively on Windows.
5. **Read-Only doesn't block `run_command_async`** (Confirmed). `renderer.js:5428`, `renderer.js:5364`. Tool names also aren't checked against the list offered to the model. Fix: reject names that weren't offered.
6. **A chat with no folder can read any file.** `renderer.js:3347`, `main.js:2259`. The "Coding" chip gives a folderless chat `read_file`, and an empty allowlist permits everything. Fix: deny file tools when there's no project root.
7. **Approval pop-ups overwrite each other.** `renderer.js:5773`. With two agents running, one click can approve a command you can no longer see. Fix: queue approvals.
8. **`web_fetch` can reach local network addresses and has no limits.** `main.js:2232-2240`. It runs without a prompt in Plan Mode, with no timeout or size cap. A malicious page could steer the model to read a file and send it out. Fix: block private addresses on every redirect, and add limits.
9. **HTML preview can reach Sanctum's API if a script runs** (frame settings Confirmed). `renderer.js:6255`. Current page rules should block inline scripts, which probably also breaks JavaScript in previews. Fix: remove `allow-same-origin`.
10. **Model-written links open inside Sanctum** (no handler Confirmed). `main.js:336-346`. They should open in your browser. The reviewers disagreed on whether such a page gets Sanctum's API: one read Electron's code and says it doesn't, the other was unsure. Test this first. Fix: deny new windows and use `shell.openExternal`.

## Wrong or lost output

11. **`apply_patch` corrupts text containing `$`** (Reproduced, Confirmed). `main.js:2324`. Replacing with `echo $$ $& done` writes `echo $ X done`. Fix: use a replacer function.
12. **Images never reach cloud models.** `main.js:1046`, `main.js:1316`, `renderer.js:4804`. Claude or Gemini can answer about an image it never received, with no warning. Fix: send the image, or refuse the attachment.
13. **Video transcripts are lost on Windows** (Reproduced for line endings only). `main.js:2078-2079`. Whisper's end marker never matches, so videos are treated as having no speech. Fix: strip `\r`.
14. **Cloud errors mid-stream look like a normal finish.** `main.js:1139-1206`, `main.js:1391-1397`. An overload or block ends as an empty or cut-off reply. Fix: emit the error.
15. **Hitting the tool step limit ends with a blank reply.** `renderer.js:5001`, `renderer.js:5027`, `renderer.js:5088`. The default limit is 5, and history also loses the assistant's text. Fix: save the text before resetting, and show a notice.
16. **Local replies stop at 16K tokens with no notice.** `renderer.js:4835`. Thinking counts toward the cap, so long scripts can end mid-code. Fix: check `done_reason` and say so.
17. **The repetition guard can cut off valid output.** `main.js:831`. Long zero-filled arrays can trigger it, and it never checks the thinking stream. Fix: raise the threshold and scan thinking too.

## Stuck or runaway work

18. **Stop can't kill code you ran from a chat** (Reproduced for ordering only). `main.js:1728`, `main.js:1740`, `main.js:1860`. The first message is sent before anything is listening, so `while True: print()` runs forever and its output grows in memory. Fix: defer the send and cap the buffer.
19. **A stray marker in model output can break chat, and possibly boot.** `renderer.js:6590`, `preload.js:93`. A literal `\x00CB9\x00` makes rendering throw, which can leave Send stuck. If saved, it can stop Sanctum launching properly. Fix: strip NULs and guard `onChunk`.
20. **Deleting a running chat doesn't stop it.** `renderer.js:297`. It keeps generating and running tools. Fix: call `stopChat` first.
21. **Queued messages get mixed into history.** `renderer.js:4641`, `renderer.js:5116`. Attachments can land on the wrong message, and failed runs leave messages stuck. Fix: filter queued messages, and drain or restore the queue on error.
22. **Background streams write into the chat you're viewing.** `renderer.js:5856`, `renderer.js:5871`. Fix: check the chat id and patch by message element.
23. **Stop doesn't work during video identify, caption, or synthesis.** `renderer.js:5145`. It says "Stopped" while the GPU keeps working for minutes.
24. **Processes survive after you quit, or get orphaned.** `main.js:1652`, `main.js:2451`, `lib/mcp-client.js:86`, `main.js:412`. On Windows only the shell wrapper is killed, and quit doesn't stop background tasks or video work. Fix: use `taskkill /T` and clean up on quit.
25. **Ctrl+R leaves a generation running with no Stop button.** `main.js:906-936`. Fix: abort when the page goes away.
26. **A bad regex from the model can freeze the app.** `main.js:2417-2437`. `(a+)+$` blocks the main process, including Stop and the watchdog. Fix: run it in a worker with a timeout.

## Memory and model fit

27. **The context suggestion can overcommit memory.** `renderer.js:796`, `renderer.js:805`. Some models count KV memory as zero, and MoE models ignore their full weights. Related to the memory problems on this machine.
28. **`num_ctx` can change mid-session.** `renderer.js:2451`. Opening Settings loads model info, which changes the value and forces a reload.
29. **The Windows GPU check fails on every machine** (Reproduced in part). `main.js:93`. It only affects machines the NVIDIA check doesn't cover: AMD and Intel machines then overstate what fits. Fix: use `-EncodedCommand`.
30. **Model info errors are remembered until restart.** `renderer.js:707`.
31. **"Unload model" can falsely say nothing was loaded.** `main.js:644`, `renderer.js:570`.

## Data loss

32. **Storage failures are silent.** `renderer.js:132`, `renderer.js:190`, `renderer.js:202`. When storage is full, later chats and settings, including API keys, are lost on restart. A corrupt store is overwritten at boot, which matters after a crash like today's. Fix: show an error and back up the raw value.

## Before the next commit or release

`lib/cloud-params.js`, `assets/fonts/`, and `test/` are new and untracked. Committing `main.js` without `lib/cloud-params.js` would stop the app from starting, and a build without the fonts would fall back to system fonts.

## Checked, no problem found

- Markdown and LaTeX rendering: no script injection, and `javascript:` links are refused.
- Escaping of chat titles, MCP data, tool cards, approval text, and web search rows.
- The `aio-media` protocol: it stays inside the cache folder.
- API keys: none found written to logs.
- `webPreferences`, including context isolation.
- Cloud model lookups: remaining `p.tag` uses only run for local models.
- Event listeners: none pile up on render.
